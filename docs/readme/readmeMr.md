### 3.1 अॅप स्थापना

| ऑपरेटिंग सिस्टम | GitHub |

| Windows | [Release](https://github.com/XXXXXLCat/Toonflow-app/releases) |
| macOS | [Release](https://github.com/XXXXXLCat/Toonflow-app/releases) |
| Android ARM64 | [APK डाउनलोड](https://github.com/XXXXXLCat/Toonflow-app/releases/latest) |

Android अॅप फक्त ARM64 उपकरणांना समर्थन देते. रिलीज पृष्ठावरून `toonflow-VERSION-android-arm64.apk` डाउनलोड करून स्थापित करा. त्यात स्थानिक Bun बॅकएंड असून ते स्वतंत्रपणे चालू शकते. होम पृष्ठावरील «डिव्हाइस जोडणी» वापरून QR कोड स्कॅन करता येतो किंवा माहिती भरून स्थानिक नेटवर्क किंवा इंटरनेटवर शेअरिंग सुरू असलेल्या संगणक किंवा बॅकएंडशी जोडता येते.

Windows इंस्टॉलर स्वयंचलितपणे WebView2 ओळखतो आणि स्थापित करतो. इंस्टॉलेशननंतर लगेच ॲप बंद झाल्यास, [WebView2 डाउनलोड पेज](https://developer.microsoft.com/microsoft-edge/webview2/) वरून रनटाइम मॅन्युअली डाउनलोड करा आणि इंस्टॉल करा.

macOS (Apple Silicon) वर Toonflow ला Applications फोल्डरमध्ये ओढा आणि थेट उघडा. त्याआधी Terminal मध्ये कोणतीही कमांड चालवण्याची गरज नाही. macOS ने सुरक्षेचा इशारा दाखवल्यास खालील पायऱ्या क्रमाने करा.

<details>
<summary><strong>macOS वर Toonflow स्थापित होत नसेल किंवा उघडत नसेल तर</strong></summary>

**1. गोपनीयता आणि सुरक्षितता मध्ये Toonflow ला अनुमती द्या**

डेव्हलपरची पडताळणी केली जाऊ शकत नाही किंवा Apple दुर्भावनापूर्ण सॉफ्टवेअरसाठी ॲप तपासू शकत नाही अशी चेतावणी तुम्हाला दिसल्यास, प्रथम Toonflow उघडण्याचा प्रयत्न करा. त्यानंतर सिस्टम सेटिंग्ज → गोपनीयता आणि सुरक्षितता वर जा, Toonflow अवरोधित करण्यात आलेला संदेश शोधा, तरीही उघडा क्लिक करा आणि सूचित केल्यानुसार पुष्टी करा. पहा [Apple च्या अधिकृत सूचना](https://support.apple.com/zh-cn/102445).

**2. अलग ठेवण्याचे निर्बंध अजूनही उघडण्यास प्रतिबंध करत असल्यास, अलग ठेवण्याचे गुणधर्म काढून टाकण्याचा प्रयत्न करा**

ॲप अधिकृत प्रकाशन पृष्ठावरून आला आहे आणि अनुप्रयोगांमध्ये आहे याची पुष्टी केल्यानंतर, टर्मिनलमध्ये खालील आदेश चालवा आणि तो पुन्हा उघडण्याचा प्रयत्न करा. ॲपचे नाव किंवा इन्स्टॉलेशन स्थान वेगळे असल्यास पथ समायोजित करा.

```bash
sudo xattr -rd com.apple.quarantine /Applications/toonflow.app
```

**3. शेवटचा उपाय: कुठूनही ॲप्सना तात्पुरती अनुमती द्या**

पहिल्या दोनपैकी कोणतीही पद्धत काम करत नसल्यास आणि ॲपच्या स्त्रोतावर तुमचा विश्वास असल्यास, चालवून पहा:

```bash
sudo spctl --master-disable
```

नंतर System Settings → Privacy & Security उघडा. Security विभागातील “Allow applications downloaded from” हा पर्याय “Anywhere” करा, जर तो तुमच्या प्रणालीत उपलब्ध असेल, आणि सूचनेनुसार पुष्टी करा. macOS च्या आवृत्तीनुसार उपलब्ध पर्याय व कमांडचे समर्थन बदलू शकते.

हे सर्व ॲप्ससाठी सुरक्षा निर्बंध शिथिल करते. त्यानंतर, आम्ही "App Store आणि ओळखले डेव्हलपर" वर सेटिंग पुनर्संचयित करण्याची शिफारस करतो.

### 3.2 Docker स्थापना

प्रथम Git, [Docker Engine](https://docs.docker.com/engine/install/) आणि Docker Compose स्थापित करा. Windows व macOS वर Docker Desktop चा Linux container mode वापरता येतो. रिपॉझिटरीमध्ये [Dockerfile](../../Dockerfile), [Compose कॉन्फिगरेशन](../../compose.yaml) आणि [बिल्डमधून वगळण्याचे नियम](../../.dockerignore) आहेत. इमेज Bun 1.3.14 वापरून तयार होते आणि त्यात FFmpeg समाविष्ट आहे.

<details>
<summary><strong>Docker स्थापनेच्या पायऱ्या उघडा</strong></summary>

स्त्रोत क्लोन करा आणि रेपॉजिटरी रूटमध्ये खालील चालवा:

```sh
git clone https://github.com/XXXXXLCat/Toonflow-app.git
cd Toonflow-app
docker compose up -d --build
```

प्रथम बिल्ड अवलंबित्व स्थापित करते आणि एकत्रित नोड्स, टूल्स, Web आणि Server तयार करते. एकदा सुरू केल्यानंतर, `http://127.0.0.1:3000` उघडा. रिमोट होस्टसाठी, खाली "प्रवेश आणि डेटा" खाली वर्णन केल्याप्रमाणे SSH बोगदा वापरा. पहिले स्टार्टअप बंडल केलेले प्लगइन सुरू करते आणि `myProject` कार्यरत निर्देशिका प्रदान करते.

सेटिंग्ज, प्लगइन आणि प्रकल्पाच्या फाइल्स `toonflowData` नावाच्या Docker volume मध्ये साठवल्या जातात. कंटेनरमध्ये तो `/app/data/` येथे जोडलेला असतो. प्रत्यक्ष volume नावाच्या सुरुवातीला Compose प्रकल्पाचे नाव असते. कंटेनर थांबवला किंवा पुन्हा तयार केला तरी डेटा सुरक्षित राहतो. **`docker compose down -v` वापरू नका: ही कमांड डेटा volume हटवते.**

```sh
docker compose logs -f toonflow  # View logs
docker compose stop             # Stop the service
docker compose start            # Start it again
docker compose down             # Remove containers, retaining the data volume
```

प्रोजेक्ट डिरेक्ट्री जोडण्यासाठी, "Server वर्किंग डिरेक्ट्री निवडा" डायलॉगमध्ये "नवीन फोल्डर" वर क्लिक करा. डायलॉग फायली आणि फोल्डर्सचे नाव बदलणे आणि हटविणे देखील समर्थन करतो. वैकल्पिकरित्या, सेवा चालू असताना कमांड लाइनमधून एक निर्देशिका तयार करा:

```sh
docker compose exec toonflow mkdir -p /app/data/workspaces/newProject
```

बॅकअपसाठी, प्रथम सेवा थांबवा, डेटा कॉपी करा, नंतर रीस्टार्ट करा:

```sh
docker compose stop
docker compose cp toonflow:/app/data ./toonflowBackup
docker compose start
```

</details>

### 3.3 Server स्थापना

Web आणि Server थेट Linux सर्व्हरवर चालवण्यासाठी हा पर्याय वापरा. खालील उदाहरण Ubuntu / Debian आणि प्रकल्पाची निर्दिष्ट आवृत्ती, [Bun 1.3.14](https://bun.sh/docs/installation) वापरते.

<details>
<summary><strong>सर्व्हर स्थापनेच्या पायऱ्या उघडा</strong></summary>

रनटाइम वातावरण स्थापित करा:

```sh
sudo apt-get update
sudo apt-get install -y git curl unzip ffmpeg
curl -fsSL https://bun.com/install | bash -s "bun-v1.3.14"
export PATH="$HOME/.bun/bin:$PATH"
bun --version
```

स्त्रोत क्लोन करा आणि सेवा सुरू करा:

```sh
git clone https://github.com/XXXXXLCat/Toonflow-app.git
cd Toonflow-app
bun install --frozen-lockfile

# Build bundled nodes, tools, Web, and Server
bun run build:server
mkdir -p data/workspaces/myProject
bun run start:server
```

“服务启动成功” (सेवा यशस्वीपणे सुरू झाली) दिसल्यावर सर्व्हरवरच `http://127.0.0.1:3000` उघडा. वरील कमांड foreground मध्ये चालते; ती थांबवण्यासाठी `Ctrl+C` दाबा. संगणक सुरू होताना सेवा आपोआप सुरू करण्यासाठी आणि प्रक्रिया व्यवस्थापनासाठी [Bun चे systemd मार्गदर्शन](https://bun.sh/guides/ecosystem/systemd) पाहा. कार्यरत निर्देशिका म्हणून रिपॉझिटरीची निर्देशिका द्या. सुरुवातीच्या कमांडमध्ये Bun चा पूर्ण पाथ आणि त्यानंतर `run start:server` असावे. त्या निर्देशिकेत वाचन व लेखनाचा अधिकार असलेल्या वापरकर्त्याने सेवा चालवावी.

</details>

### 3.4 प्रवेश आणि डेटा

- सेवा सध्या निश्चित पोर्ट `3000` वापरते. वेब इंटरफेस आणि API मध्ये वेगळे लॉगिन प्रमाणीकरण नाही. सर्व्हर स्थापनेसाठी, फायरवॉल किंवा सुरक्षा गटाद्वारे `3000` पोर्टवर प्रवेश प्रतिबंधित करा. सार्वजनिक प्रवेशासाठी प्रमाणीकरणासह रिव्हर्स प्रॉक्सी आवश्यक आहे.
- वैयक्तिक दूरस्थ प्रवेशासाठी, तुमच्या स्वतःच्या संगणकावर `ssh -N -L 3000:127.0.0.1:3000 username@server-address` चालवा. कनेक्शन उघडे ठेवा, नंतर `http://127.0.0.1:3000` ला भेट द्या. तुम्हाला सर्व्हरचे पोर्ट `3000` सार्वजनिक इंटरनेटवर उघड करण्याची गरज नाही.
- थेट इन्स्टॉलेशनसह, सेटिंग्ज, प्लगइन्स आणि वर्कस्पेस डीफॉल्टनुसार रेपॉजिटरीच्या `data/` निर्देशिकेमध्ये संग्रहित केल्या जातात. Docker सह, ते डेटा व्हॉल्यूममध्ये `/app/data/` वर संग्रहित केले जातात. स्थलांतरित किंवा बॅकअप घेताना संपूर्ण निर्देशिका जतन करा. पृष्ठ उघडल्यानंतर, सर्व्हर वर्कस्पेसमध्ये `myProject` निवडा. अतिरिक्त प्रकल्पांसाठी संबंधित `workspaces/` निर्देशिका अंतर्गत उपनिर्देशिका तयार करा.
- दोन्ही इन्स्टॉलेशन पद्धतींमध्ये FFmpeg प्रणाली समाविष्ट आहे. तुम्हाला अजूनही इंटरफेसमधील मॉडेल सेवांसाठी API की कॉन्फिगर करण्याची आवश्यकता आहे.
