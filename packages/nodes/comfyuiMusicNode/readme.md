# ComfyUI-音乐生成

接入本地 ComfyUI 的**音乐生成工作流**。与「ComfyUI-音频生成」是并列关系：那边做语音合成（TTS），这边做曲子生成。当前支持两个工作流：

- **YuE2 音乐生成**（`yue2Music`）：从风格描述与歌词直接出完整编曲。
- **YuE2 音乐翻唱**（`yue2Cover`）：先把你接入的参考音频转成 ABC 记谱，再按风格与歌词重新编曲。

## 输入与输出

- **文本、音频输入**（画布左侧端口）：文本接风格与歌词；音频只有翻唱类模型会消费。
- **音频输出**（画布右侧端口）：生成的曲子，可接入音频节点或导出。

顶部还有「截取」「变速」「替换音频」三个操作，与音频节点一致。

## 参数

| 参数 | 说明 |
|---|---|
| **Text (Style)** | 风格描述（工作流的 `style`）。写曲风、编曲、配器、情绪，如 `cinematic orchestral with strings and taiko drums` |
| **Text (Lyrics)** | 歌词（工作流的 `lyrics`）。支持 `[Verse]` / `[Chorus]` 等段落标记；纯器乐可留空 |
| **时长上限** | 秒，10 ~ 900 步长 5，默认 360。提示词过长时 ComfyUI 会自动缩短，实际也可能提前结束 |
| **输出格式** | MP3 / FLAC / Opus（`SaveAudioAdvanced` 只支持这三种） |
| **音质** | 格式的二级入参：MP3 是 `V0` / `128k` / `320k`，Opus 是 `64k` ~ `320k`；FLAC 无损没有这一项 |
| **随机种子** | 每次随机便于挑选；听到满意的切到「固定」就能复现它 |

接上游文本时按先后顺序分配：**第 1 条并入风格描述，第 2 条及以后并入歌词**（编号沿用引用在列表中的位置，与 `@` 提及对得上）。

## 说明

- **模型下拉只列音乐模型**。供应商用 `audioCategory: "music"` 声明归属；不声明的按语音合成处理，出现在「ComfyUI-音频生成」里。两个节点因此不会列出同一批模型。
- **没有模式选择**。工作流的模式是写死的：文本生成固定 `full`（旋律 + 和弦），翻唱固定 `melody`（转谱产出的是旋律谱，只能配旋律模式）。画布给一个改了不生效的下拉没有意义。
- **参考音频按模型能力生效**。模型用 `referenceAudio` 声明它会消费接入的音频；未声明的模型接了音频会被忽略并给出提示，不会静默丢弃。用 `requiresReferenceAudio` 声明的模型（翻唱）没接音频时直接拦住生成——没有音频就转不出谱，提交了也必然失败。
- 时长上限通过请求的 `other` 通道下发给供应商——不同音乐工作流的参数差异太大，不适合逐项进平台白名单。
- 种子上限是 `2^32-1`（跟着 YuE2 的 `SeedNode` 走），与语音节点的 `2^31-1` 不同。
- 停止生成会撤销已提交到 ComfyUI 的任务（执行中的中断、排队中的移除），不会继续占用显存。
