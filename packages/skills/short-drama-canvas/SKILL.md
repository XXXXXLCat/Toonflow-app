# 短剧画布施工

本技能是创作文档与 Toonflow 画布之间的唯一通道。创作事实仍住在项目 Markdown 里，
画布只是它们的执行形态：节点承载提示词与参数，连线复现文档已经写明的参考关系。

不创造上游没有的内容。文档里没写的镜头、参考、参数，不在画布上补齐。

## Quick Start

先跑一遍施工计划，把文档解析成节点清单与连线清单：

```bash
python3 {技能目录}/scripts/board_plan.py <project> --episode <EP> --pretty
```

脚本只读文档、只输出计划，不写文件、不碰画布、不调用供应商。拿到计划后再询问
**目标模型**（图片与视频各一个），因为它决定 `providerId`/`modelId` 与可用档位：
先用 `getCanvas({include:["nodeTypes"]})` 确认画布实际启用了哪些节点类型，
再用节点的 `node:getConfig` 读该节点实际可用的模型与档位。不替创作者默认选模型。

计划里的三处需要留意：

- `stats.dangling_items` 非空：文档引用了不存在的条目，回对应 owner 修文档，不在画布上猜。
- `stats.empty_prompts` 非空：条目缺可复制提示词，同样回 owner 补。
- `nodes[].reference_state` 为 `待补参考图` 或 `待解析`：参考还没落成真实文件，
  建节点可以继续，但这一镜不能声称已有参考。

## 画幅：项目开始时定一次

成片画幅不是每镜的独立选项，它是**项目级事实**，住在 `short-drama.json` 的 `format.aspect_ratio`，
由 `$short-drama` 在项目初始化时与创作者确认一次（该脚本属于 `$short-drama` 技能）：

```bash
python3 <short-drama>/scripts/project_tool.py init <project> --title "<标题>" --aspect-ratio 9:16
```

之后所有阶段都从档案读它，**不再逐镜询问、也不逐节点调整**。确认一次，全流程沿用。

项目已经建好、画幅当时留了 `unset`，或要变更画幅时，用本技能的读数/写值脚本，不必重建项目：

```bash
python3 {技能目录}/scripts/board_ratio.py <project>            # 读：档案值、视觉设定值、是否冲突
python3 {技能目录}/scripts/board_ratio.py <project> --set 9:16 # 写：改档案的成片画幅
```

`board_plan.py` 已经按这个顺序取值：项目档案 → `视觉设定.md` → 都没有才报缺失。
两处不一致时以**档案**为准，并在 `stats.ratio_conflict` 里如实报出，请创作者回对应 owner 统一文档。
`stats.ratio_missing` 为真说明画幅还没定：**先问一次并写入档案**，不要靠默认值建图。

进画布时的应用范围：

| 节点 | 画幅 | 原因 |
|---|---|---|
| `SHOT-*` 关键帧 | 成片画幅（如 `9:16`） | 它就是成片的画格 |
| `MOTION-*` 视频 | 成片画幅 | 同上 |
| `IMG-*` 资产板 | `自适应`，或条目「画幅」字段显式指定 | 资产板是素材，出图比例由版式决定（多角度分段板 4:3、双格场景板），不受成片画幅约束 |

`IMG-*` 的 `ratio` 默认是 `自适应`（写死的常值，不读成片画幅）。条目要让生成端锁定一个
确定比例时（如多角度分段板写 `- 画幅：4:3`），脚本会取该字段里的比例覆盖 `自适应`；
字段缺失或写不出比例就仍是 `自适应`。**同一批资产板里只用一种**，混用会让同批参考图
结构不统一。

`SHOT-*` 与 `MOTION-*` 在个别人物特写或构图另有要求时，也可在条目「画幅」字段里写明覆盖
成片画幅——但那是例外，不是常规路径；没有该字段就一律沿用档案值。

改画幅属于项目级决定：由 `$short-drama` 走创作者决策流程改写档案，再重新导出画布，
不在画布上逐节点改 `ratio`。

## 条目到节点

三种条目对应两类节点，节点类型名以 `getCanvas` 返回的 `availableNodeTypes` 为准
（本机形态为 `remote-comfyuiImageNode`、`remote-comfyuiVideoNode`）：

| 文档条目 | 节点 | 提示词取 | 参数 |
|---|---|---|---|
| `图片提示词.md` 的 `IMG-*` | 图片节点 | `### 可复制提示词` 正文 | `ratio` 用「自适应」；`megapixels` 取 `getConfig` 返回的档位 |
| `分镜.md` 的 `SHOT-*` | 图片节点 | `### 冻结关键帧提示词` 正文 | `ratio` 取档案的成片画幅；`megapixels` 同上 |
| `视频提示词.md` 的 `MOTION-*` | 视频节点 | `### 可复制提示词` 正文 | `duration` 取「时长」；`ratio` 取档案的成片画幅；`mode` 按「生成方式」 |

提示词正文以 `>` 开头的引用块形式存在，写进节点时去掉行首引用标记，保留正文原样，
不改写、不压缩、不翻译。节点标签用条目 ID 与标题，如 `SHOT-EP001-002 · 四个号，四个粉`。

参数一律先 `node:getConfig` 读当前值与可选范围，再 `node:setConfig` 写入，
`providerId` 与 `modelId` 成对提供。档位只取 `getConfig` 返回值里实际存在的项；
目标节点没有对应字段时说明缺项，不把参数硬塞进提示词。

## 连线

连线依据全部来自文档，分两类，语义不同，不要混为一谈：

**结构性连线**（`MOTION-*` 的「分镜」字段指向的 `SHOT-*`）：关键帧节点连到视频节点，
表示这一镜的画面来源。文档写了就必连，不因创作者选择文生视频而断开——
文生视频说的是不送参考图，不是这一镜与关键帧无关。

**参考性连线**（`SHOT-*` 的「图片提示词项」字段列出的 `IMG-*`）：资产图节点连到关键帧节点。
这类连线表达的是**计划中的引用结构**，建图时就该连上，否则关键帧节点不知道该拿哪张板当参考。
它与文档里那条「文件此刻在不在项目里」的轴不是一回事：

- **画布连线**＝这一镜打算接哪几张图，属于施工图，随节点一起建；
- **《分镜.md》的「输入参考图」**＝这次实际送哪些文件，只有真实文件才算 `REF-...`。

两者不矛盾，但生成有先后：**先出资产板，再出关键帧，最后出视频**。资产板还没生成时，
连着的关键帧节点会因为没有图而生成失败——这正是顺序约束在起作用，不是配置错误。

「图片提示词项」与「输入参考图」是两条独立的轴：前者说这一镜打算用哪些资产图，
后者说这次实际送哪些文件。`输入参考图` 为 `无（创作者已明确选择文生视频）` 时，
结构性连线照连，参考性连线按上一条判断。

`REF-*` 槽位（`输入参考图` 里的真实文件）连到目标节点的 `in` 端口，
顺序按槽位的「顺序：n」排列；`用途：起始帧`/`结束帧` 对应视频节点的首尾帧输入位。
连线前用 `getCanvasNodes` 的 `ports` 确认端口 ID 与类型，不猜端口名。
跨类型的 `in` 端口（图片、视频、音频、文本）按素材实际类型接入。

## 一次性导出画布

一集几十个节点时，可以不逐个 `addNode`，直接导出整集画布：

```bash
python3 {技能目录}/scripts/board_apply.py <project> --episode <EP> --out <EP>.canvas.json
```

产出由创作者导入工作区。结果与逐个调用画布工具一致，差别只在速度。
**只导出新文件，不修改任何正在打开的画布**：运行中的画布仍然只经画布工具与节点函数改动，
不直接写 JSON。导出用于「首次建图」与「换机重建」，不用于「改动已有画布」。

脚本会在计划不完整（`dangling_items` 或 `empty_prompts` 非空）时拒绝导出并列出缺项，
避免把残缺的图建出来。加 `--structure-only` 时只连结构性关系，参考连线留到资产图产出后补。

## 生成前的确认

**先展示、再确认、后生成**。这是硬闸门，不可合并、不可跳过。

建完节点与连线后，把本次要生成的内容完整列给创作者：每个节点的条目 ID、对象与数量、
目标模型与规格、会话中完整提示词、实际接入的参考、预计执行次数。使用可用的 `askUser` 提问，
没有提问工具时文字提问并等待。

算力统一称「消耗算力」，有可靠报价才展示，查不到就说明「算力消耗未知」。
以下均不构成确认：制作意愿、风格认可、提示词已看过、之前的确认、`继续`/`都做完`/`预算没问题`。

修改任何节点的提示词、参数、连线或数量后，原确认立即失效，重新展示并确认。

## 执行与核对

确认后按已授权范围执行：`node:generateImage` 或 `node:generateVideo`，参数为 `{}`，
使用节点当前配置。生成是后台任务，`generating` 只表示已开始；用 `node:getGenerationStatus`
查询完成结果，`node:cancelGeneration` 停止生成。

一集几十个节点必须**分批**：按镜序切成若干批，每批执行完回报结果再继续，
不一次性发出全部生成。失败先按错误修正，重试前核对已有输出，避免重复消耗算力。

生成完成后核对实际产出：图片节点看输出图片，视频节点看输出视频。
只存在文件、只看过静帧，都不等于看过完整结果；未核对的部分如实说明。

## 与生成技能的边界

本技能负责「文档 → 画布 → 触发生成」。上游内容归各 owner：

- 提示词怎么写：`$short-drama-image-prompts`、`$short-drama-video-prompts`
- 镜头怎么分：`$short-drama-storyboard`
- 资产与连续性：`$short-drama-assets`
- 台词与录音：`$short-drama-write`

`$short-drama-produce` 走的是项目外的 adapter 路线（`production_tool.py`），与本技能的
画布路线并列。用户要走画布时用本技能，不要在画布之外另建生产通道，也不要把 adapter
凭据带进画布流程。成片剪辑仍归 `$short-drama-edit`。

## 已知限制

- 本环境没有 shell，脚本一律通过 `dramaScript` 执行。本技能提供三个脚本，`skill` 一律填
  `short-drama-canvas`：`board_plan.py`（解析文档出施工计划）、`board_apply.py`（导出画布文件）、
  `board_ratio.py`（读写成片画幅）；其余参数按顺序进 `args`，项目目录用 `projectRoot` 指定。
  引用其他技能的脚本（如 `project_tool.py`）时，`skill` 填脚本实际所属的那个技能名。
- 画布节点存在前端状态里，本技能不直接改画布 JSON，全部经画布工具与节点函数操作。
- 节点类型、函数名、参数结构、可选模型都随实际安装内容变化；每次以 `getCanvas`、
  `getNodeTools`、`node:getConfig` 的返回为准，不使用本文档里的型号或档位当固定值。
