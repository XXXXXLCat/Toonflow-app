# Qwen 文生图正文方言

**适用场景**：**首次从零生成**、没有任何参考图的单张资产图——第一张人物立绘、第一版场景板、
第一件道具图。此时正文必须自己交代画面里的一切，没有参考图可依据。

**不适用**：跟随参考图的资产板（多角度分段板、状态变体、组合板），它们的正文由 A 套自己的
配方组织，见对应文件。也不适用**参考图编辑**（重绘、打光、换角度），那是由图改图。

`QWN-01` `craft_default` — 本文管**正文怎么写**（一段四五百词的英文旁观者式描述 + 一个节点比例决策）。
写什么对象、要固定哪些身份锚点、连续性锁锁面怎么写，仍由 [通用配方](common-recipe.md) 与对应资产
配方决定；本文只改变**正文的组织方式**，不改变要固定的内容。同时适用时：先按 A 套配方锁定身份、
状态、空间与禁止项，再按本文的顺序把它们写成一段英文描述。A 套要求「锁面原样出现」时，锁面照旧逐字
出现在描述里。

## 1. 正文输出契约

`QWN-02` `structural_invariant`

- **一段英文**，单行连续段落；中文需求也输出英文正文，但画面内要出现的文字保持原语言。
- 正文里**不含** JSON、键名、标签、标题、代码块、前后语、说明或收尾。
- 默认**只有一段**；确实由多层分区（面板、卡片、分区、幻灯片）构成时才分段，一个分区一段。
- 不把比例、分辨率、像素数、时间戳写进正文。
- 段首即第一个字符，段外不添加任何多余文字——写进节点的是整段正文本身。

**与 `rewritePrompt` 的关系**：按本文写出的正文是**成品**，进 `node:setPrompt` 后应把
`rewritePrompt` 关掉（`node:setConfig({ rewritePrompt: false })`）。开着它再把成品喂进去，等于把
成品重写一遍：白跑一次语言模型，还可能改动已定稿的措辞。

- **节点级默认是 `true`**（`data.rewritePrompt ??= true`），按本文写完后必须主动关掉，不能假设它是关的。
- **例外：由本仓库流程批量导出的节点默认就是关的**——`board_apply.py` 导出画布时图片与视频节点都写
  `rewritePrompt = false`（它从 `### 可复制提示词` 抽出的就是成品正文，与本文同一口径）；「制作资产」
  按钮下发的子节点也是 `false`（版式逐字写死，见[多角度分段板](multiview-sheet.md)）。
- 只有手里只有三五个词的口头需求、又不打算自己扩写时，才保留 `rewritePrompt` 打开交给工作流
  （「多角度/局部重绘/打光」三个玩法就是这种：下发含 `{{ref N}}` 的短指令，默认开重写）。

## 2. 比例写进节点配置，不写进正文

`QWN-03` `structural_invariant` — 比例不是描述的组成部分，它由节点配置决定，**完全不经过文字**。
书写时按主体定横竖，再取一个节点实际提供的档位写进 `node:setConfig`。

Qwen 图片节点只提供 8 个比例，**只能取其中之一**，写别的会被节点直接拒绝：

| 档位 | 用在 |
|---|---|
| `3:2` | 横向的默认选择 |
| `2:3` | 纵向的默认选择 |
| `1:1` | 方形徽章、图标、专辑封面、单一居中标识 |
| `16:9` | 宽银幕或演示用横构图 |
| `9:16` | 手机屏、竖版长条 |
| `3:4` | 略窄的竖构图 |
| `4:3` | 略宽的横构图 |
| `21:9` | 超宽横构图 |

参考图驱动的场景（模型 `imageCapable`，例如重绘、编辑、跟随参考图的资产图）还可选「自适应」，
表示比例跟随参考图；**纯文生图不使用它**，用它等于放弃对画幅的控制。

取档位前先用 `node:getConfig` 读 `ratioOptions` 核对，不凭记忆写数值。

## 3. 八步书写法

`QWN-04` `craft_default` — 按顺序走八步，每步锁定一个决定，后面的步不回头改前面的。

### Step 1 — 读 brief，拆成两类

先分清用户**已固定**和**留待决定**的内容。

**固定项**必须原样进入描述：要显示的文字串、点名的物件、所有数量、已声明的颜色、已声明的位置、
以及给定了的画幅。文字串**逐字符照抄**，保持原语言与标点空格。

用户还可能给**关于任务而非画面的指令**——「用双引号」「不要硬边色块」「4K，无噪点」「确保文字清晰」。
那不是内容：在适用处默默遵守，**绝不写进描述**。描述只说画面里有什么，不说要做什么。

**留待决定的**由你定：用户没提的一切。三字需求和三百字需求写出的描述**体量相同**——
短需求意味着你在编造画面的大部分，不是少写。

### Step 2 — 定画幅

按主体定横竖，再选比例（档位见上节）。用户给了比例就用它；否则横向默认 `3:2`、纵向默认 `2:3`。
**比例不属于描述**：在这里定下来记进节点参数，绝不把比例、分辨率、像素数写进描述。

### Step 3 — 写开篇句

一句话，约二十词，点名**媒介、风格、主体、背景或调色**，通常也点名横竖：

```
The image is a ⟨vertical / wide / square / tall⟩ ⟨style⟩ ⟨photograph · poster · illustration · scene · portrait · infographic · close-up · graphic · page · card · sheet · logo⟩ of ⟨subject⟩, ⟨the background and its palette⟩.
```

`This is a …` 或直接用 `A vertical realistic photograph of …` 同样成立。**媒介名词是唯一不可省略的部分。**

风格词放在这里——realistic / photorealistic / minimalist / flat-vector / cinematic / watercolour /
isometric / editorial / hand-drawn / 3D-rendered / retro。**只在这里点名一次**，可以在收束句呼应。

### Step 4 — 先清点，再动笔

写更多文字之前，先定两份清单：

- **画面里会出现的每个元素及其位置**：左上、横跨顶部、最右侧、下三分之一、中央、前方、后方、缩进角落。
  需要 **8–14 个**位置短语（通常约十个），且必须覆盖四角、边缘与中心——**不挤在中间**。
- **画面里会被读到的每段文字**，按阅读顺序。

### Step 5 — 走一遍画面

按顺序描述。顺序取决于画面怎么填满。

**画面分成多个区域时**（海报、页面、界面、版式、含多物的宽场景）——按区域走：

1. **背景及其承载面**——紧接开篇句之后，**不放在结尾**。
2. **顶部横带**：标题、页眉条、天空、天花板，任何占据顶边的东西。
3. **沿画面主体向下横向推进**：左侧 → 中央 → 右侧。每个区域一到两句。
4. **底部横带**：页脚、前景、地面、底行。

**单一主体填满画面时**（肖像、特写、单个物件）——走主体本身：背景及其衰减程度 → 主体的姿态与
在画面中的位置 → 头部与面部 → 身体与每件衣物或表面 → 所持或接触的东西 → 边缘剩余的零星细节。
在主体内部继续用位置短语（画面左上、左肩后方、下缘）让画面始终可定位。

**约三分之一的句子应以位置短语开头**——`On the right side of the frame, …`、`In the upper-left corner, …`、
`Across the lower third, …`——让读者始终知道在看哪儿。

**保持一段**。只有画面确实由堆叠区域构成（面板、卡片、分区、幻灯片）时才分段，一个区域一段，
每段以该区域所在位置开头。

### Step 6 — 逐段设定文字

画面里没有需要读的内容时**跳过本步**——三分之一的图没有任何可读文字，给它编造招牌是错的。

否则按 Step 4 清单、依阅读顺序，逐串说明它**在哪里、长什么样、写的是什么**：
`a bold black headline across the top reads "…"`。

文字串用**直双引号**，保持原语言——中文、俄文、韩文、日文、阿拉伯文留在各自的语言里。
说明字重、颜色、大小写与相对尺寸。换行写成「第二行」，不要真的在串里放换行符。
**不该读的标记**（远处招牌、玻璃后的标签、密集正文）写成模糊、不清晰或「小到看不清」，**不编造字母**。
画面里若有图表或表格，其坐标轴、刻度标签、图例项、系列名与单元格值也是文字：全部写出来。

### Step 7 — 给光单独一句

每张图都有光，描述总要交代它：来源、方向、质感、以及它留下的阴影与高光。
左窗柔和散射日光、顶部硬质棚拍光、温暖低角度日光、示意图用平坦均匀环境光。

内容摆好后给它单独一句——`The lighting is …`——或者当光正是让某个表面呈现特定观感的原因时，
并进那个表面的句子里。两种情况都**显式写出，不隐含**。

### Step 8 — 以整幅画面收束

以一句退后一步的话结尾：

```
The overall composition ⟨is / uses / feels⟩ …
```

`The composition is …`、`The overall design …`、`The overall mood …`、`The overall palette …`、
`The image has …` 是同一个动作。在这一句里覆盖平衡与对称、调色、风格与情绪。
**只写一句**，后面不再跟第二句总结。

## 4. 贯穿全文的要求

`QWN-05` `craft_default`

- **体量**：描述约二十句、四五百词，平均每句约二十五词。无论 brief 是三个词还是三百个词，体量相同：
  区域多、文字密的画面更长，单一安静主体更短，但**稀薄的 brief 永远不会换来稀薄的描述**。
- **只观察，不指令**：现在时、第三人称、陈述句。不要 `you`、`create`、`make sure`、`the AI should`。
  不要质量词——不要 `masterpiece`、`8K`、`highly detailed`、`award-winning`。
- **不确定的就留余地**：观察者描述图片时会说 `appears to be`、`likely`、`suggesting`，并在确实含糊时
  给一对选择——`a notebook or a tablet`、`wood or dark laminate`。**多用这种写法**，它才是这里自然的语气。
  只有用户固定的内容才写得斩钉截铁。
- **颜色必带修饰词，几乎不用裸色名**：deep navy、muted olive、pale cream、warm terracotta、
  soft dusty rose、blue-grey、off-white、charcoal、brownish-green。**只有用户给了十六进制值才用它**。
- **给材质，不只是名词**：brushed metal、matte plastic、glossy ceramic、coarse linen、weathered wood、
  frosted glass、grain、scuffs、condensation、visible brush strokes、paper fibre。
- **逐个列举，绝不概括**：`several items`、`various decorations` 不是描述。说清每件是什么。
  小数量写英文单词——three、five、twelve——部分被遮住就说明并描述可见部分。
- **人物只写可观察的外表**：体格、姿态、视线方向、表情、头发、肤色，以及每件衣物的颜色与材质。
  **年龄写成生命阶段或年代**——a child、a teenager、a young adult、middle-aged、elderly、in her thirties——
  **绝不写具体岁数**。脸转开了或被裁掉了，就这样说，别去描述它。
- **物件按类别写，不按品牌**：a silver laptop、a mirrorless camera、a compact hatchback——
  除非用户点了品牌。摄影与设计词汇随意用：shallow depth of field、bokeh、backlit、close-up、
  negative space、grid、drop shadow。
- **物理上自洽**：阴影背离光源、反射与表面前方的物体相符、相邻物体尺度一致、表面会因承托物产生反应。
  用户要了不可能的东西，就按画面呈现的样子描述，让场景其余部分保持连贯。

`QWN-06` `structural_invariant` — 描述**永远用英文**，无论请求用什么语言到来。
唯一例外是**画面内显示的文字**，它保持自己的语言。

## 5. 交稿前自检

`QWN-07` `structural_invariant` — 逐项核对：

- 是一段英文，段内没有比例、分辨率、像素数、时间戳。
- 段首即第一个字符，段外没有任何多余文字。
- 位置短语 8–14 个，覆盖四角、边缘与中心，没有挤在中间。
- 约三分之一句子以位置短语开头。
- 结尾只有一句整体收束，没有第二句总结。
- 画面内文字逐字保留原语言；不该读的标记写成模糊或不可辨，不编造字母。
- 全文没有「不要/不得/确保」式指令句——描述只说画面里有什么。
- 没有 `masterpiece`、`8K`、`highly detailed` 这类质量词。
- 年龄写成生命阶段或年代，不写具体岁数。
- 对象按类别写，不写品牌（除非用户点名）。
- 比例取自节点 `getConfig` 实际返回的档位。

改写标准与 `qwenImage21` 工作流内置的重写器同源；工作流的重写器提示词更新时，本文的书写标准需同步。
