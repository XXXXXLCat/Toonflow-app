# 短剧背景音乐设计

背景音乐按**情绪**走，不按镜头走。一集几十个镜头若各配一段乐，观众听到的是一份音效清单；
真正需要的是一条随情绪起伏、跨镜头连续铺开的音乐线。

产物是一份《配乐本.md》，以及在画布上按乐段落成的音乐节点。

## 角色分工

| 产物 | 归属 | 本技能做什么 |
|---|---|---|
| 镜头目的、景别、时长 | `分镜.md`（归 `$short-drama-storyboard`） | 只读，作为情绪依据 |
| 场次与剧情功能 | `剧本.md`（归 `$short-drama-write`） | 只读 |
| 乐段划分、风格描述、时长 | 《配乐本.md》（本技能新建） | 全权负责 |
| 时间线音乐章节的意图叙述 | `视频提示词.md`（归 `$short-drama-video-prompts`） | 不写；本技能是它的可执行版本 |
| 混音落点、循环、对白 ducking | 归 `$short-drama-edit` | 不做 |
| 实际生成 | `$short-drama-produce` 的 `music` 模态 | 只出设计，生成要经确认闸门 |

## Quick Start

```text
用 $short-drama-music 按 EP001 的分镜设计配乐，几个人物对话多的段落别铺太满
```

```bash
# 1. 读分镜出的情绪曲线，列出候选乐段与每段覆盖的镜头
python3 {技能目录}/scripts/music_plan.py <project> --episode EP001 --pretty

# 2. 文档定稿后导出画布：每段乐一个音乐节点
python3 {技能目录}/scripts/music_apply.py <project> --episode EP001 --out EP001.music.canvas.json
```

脚本一律通过 `dramaScript` 执行，`skill` 填 `short-drama-music`，`projectRoot` 填项目根目录。
本环境没有 shell。

## 第一步：从分镜读出情绪曲线

乐段的边界不在镜头上，在**情绪变化**上。读两个来源：

- `分镜.md` 每个 `SHOT-*` 的 **`目的`** 字段：它写的是「这一镜是干什么用的」，
  是情绪判断最可靠的依据（如「开场第一拍就给压力」「先把一切如常立住，坏消息才有对照面」）。
- `剧本.md` 的场次划分：一场通常是一个完整的情绪单元。

**怎么定乐段边界**：相邻镜头若在做同一件事（同一场、同一股压力、没有转折），
就是同一乐段；一旦出现下面任一种变化，边界就落在这里：

- **场次切换**（SC001 → SC002，空间与人物全换）；
- **情绪转向**（从奔逃的紧张 → 停下喘息的短暂松弛）；
- **叙事功能切换**（从铺垫 → 揭示，从对峙 → 和解）；
- **静场**（有意的沉默，该段不铺乐，见下）。

**一段跨几个镜头是常态**，不是例外。EP001 的 12 个 SC001 镜头，情绪上大约只落 2–3 段。

`music_plan.py` 会按场次与目的字段先出一版候选划分，供你调整；它不做艺术判断，
边界最终由你定。

## 第二步：每段写什么

产物是 `剧集/<EP>/配乐本.md`。每段一条：

```markdown
## MUSIC-EP001-01 · 雾中奔逃

- 覆盖镜头：MOTION-EP001-001 ~ MOTION-EP001-003、MOTION-EP001-007、MOTION-EP001-008
- 场次：EP001-SC001
- 剧情功能：建立「雾里是危险的」这件事，把压力从第一秒压上来
- 情绪走向：持续紧张 → 在最后两镜转为凝滞的不安（音色不变，密度下降）
- 时长：48s
- 进出：从 0 秒直接进入（不给前奏）；到本段最后一镜结束时收在悬停和弦，不落地
- 风格描述：（英文，见下）
- 禁用：避免明确的旋律线条与强节拍，避免鼓组
- 歌词：无（纯旋律）
```

### 风格描述怎么写

风格描述是这个节点唯一进模型的文本（节点上的 `Text (Style)`）。控制四件事：

1. **乐器编制**：写清主奏与铺底（如 `solo cello with sustained low strings under sparse high piano`）；
2. **节奏与速度**：`slow`, `at a walking pace`, `no percussive pulse` 这类；
3. **调性与色彩**：`minor key`, `modal`, `dissonant intervals`, `warm major`；
4. **情绪走向**：由低到高、逐层加厚、密度下降——写**能听出来的变化**，不写「悲伤」「紧张」这类概括词。

写成一段英文描述，与视频提示词的写法一致。示例：

```text
Slow modal strings in a minor key, solo cello carrying a thin sustained line over a low
drone, no percussive pulse and no clear melodic hook; the texture thins toward the end,
leaving a suspended unresolved chord. Restrained, cold, uneasy.
```

### 时长怎么定

音乐节点一次生成只有**一个时长上限**，没有精确裁切。所以：

- **宁长勿短**：时长的取值要覆盖整段，由 `$short-drama-edit` 在剪辑时裁到落点。
- 时长按该段覆盖镜头的**实际时长之和**取，向上取到 5 秒的整数倍（节点步长）并留 10–15% 余量。
- 节点可选范围 10–900 秒；单段超过 900 秒要再切分——但正常乐段不会这么长。
- `music_plan.py` 会按分镜的时长字段算好每段的建议时长。

### 歌词一律留空

本技能只做**纯旋律**。歌词字段一律不写，节点上的 `Text (Lyrics)` 保持空。
需要主题曲或人声唱段时，那是另一条路径（`视频提示词.md` 的时间线音乐章节 +
已确认歌词），不在本技能范围内。

### 静场是有意的决定

有些段落**不该有音乐**——沉默本身就是设计。出现下面情况时，不建乐段，
但在配乐本里明确写一条 `- 静场：MOTION-... ~ MOTION-...（原因）`：

- 台词密度极高、需要观众听清每一句的对话段；
- 情绪需要「抽空」的时刻（死亡、真相揭晓的瞬间）；
- 前后两段需要被隔开的强对比点。

记下来，是为了让「没有音乐」看起来是决定，不是遗漏。

## 第三步：落到画布

乐段定稿后，每个乐段建 **1 个音乐节点**：

| 文档事实 | 画布形态 |
|---|---|
| 乐段 | 1 个音乐节点，标签 `MUSIC-<乐段号> · <段落名>` |
| 风格描述 | 该节点的 `Text (Style)` |
| 时长 | 该节点的 `maxDuration` |
| 歌词 | 留空 |

节点类型名以 `getCanvas` 返回的 `availableNodeTypes` 为准（本机形态为 `remote-comfyuiMusicNode`）。
参数一律先 `node:getConfig` 读当前值与可选范围，再 `node:setConfig` 写入，
`providerId` 与 `modelId` 成对提供。

**音乐节点不接视频节点**。背景音乐是**产出物**，供剪辑铺轨，不是视频生成的输入参考。
把它接到视频节点的音频输入上，会让模型把配乐当成音色参考来处理，语义是错的。
视频节点上的音频输入留给 `$short-drama-voice` 的人物参考音频。

### 导出的画布文件

`music_apply.py` 产出独立的 `.canvas.json`。与 `$short-drama-canvas`、
`$short-drama-voice` 的画布合并时用 `--merge`——三个脚本共用同一套节点 ID 命名空间，
但音乐节点不与任何节点连线，所以合并只是把节点追加进去。

## 生成前要说的

音乐节点建好不等于要生成。实际生成走 `$short-drama-produce` 的 `music` 模态：
先展示本次要生成的每段风格描述、时长与数量，取得明确确认后再执行。
确认规则归那个技能，本技能不代它确认。

生成后要把**实际产物路径**回填到配乐本的 `- 生成结果：` 一行，
供 `$short-drama-edit` 找到音轨。

## 边界

- **不写歌词**：一律纯旋律。人声唱段是另一条路径。
- **不做混音**：进入退出点、循环、对白 ducking、响度归 `$short-drama-edit`。
- **不改分镜**：镜头划分归 `$short-drama-storyboard`，本技能只读它的目的与时长。
- **不生成视频**：本技能不碰视频节点与视频提示词。
- **不代替确认**：生成要经 `$short-drama-produce` 的确认闸门。

## 已知限制

- 乐段划分是艺术判断，脚本只给候选；边界由创作者定。
- 音乐节点无精确裁切能力，时长是上限，落点由剪辑完成。
- 节点类型、函数名、参数结构随实际安装内容变化；每次以 `getCanvas`、
  `getNodeTools`、`node:getConfig` 的返回为准，不使用本文档里的型号当固定值。

## 按需知识
