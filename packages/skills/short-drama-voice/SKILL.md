# 短剧人物配音

本技能管三件事，顺序固定：**给人物定音色** → **写出他每一句怎么说** → **把音色接回他每一句话**。

音色是**人物身份**的一部分，跨集稳定；一句台词用什么语气说是**表演**，逐句决定。
两者都不住在画布里——画布只是执行形态。先写文档，再落画布。

## 角色分工

| 产物 | 归属 | 本技能做什么 |
|---|---|---|
| 台词原文与表演括注 | `剧本.md`（归 `$short-drama-write`） | 只读，不写 |
| 音色参考与选型判据 | 《视觉设定.md》的「声音方向」（归 `$short-drama-assets`） | 按需补齐本技能所需的参考与指令字段 |
| 逐句语气与朗读文本 | 《配音本.md》（本技能新建） | 全权负责 |
| 音频节点、语音指令、参考连线 | 画布 | 全权负责 |

台词不由本技能改写。配音本里的「朗读文本」必须与 `剧本.md` 原句逐字一致，
只在它前面加语气说明——改词是写作者的事，不是配音的事。

## Quick Start

```text
用 $short-drama-voice 给 EP001 的每个人物定音色，写出配音本，并接到画布上
```

三步走，每步都有脚本可以先出计划：

```bash
# 1. 扫人物与他们的台词，列出谁要配音、每人几句、哪几句缺语气
python3 {技能目录}/scripts/voice_plan.py <project> --episode EP001 --pretty

# 2. 把人物的音色落成可执行的合成请求（每个新人物一条试听）
python3 {技能目录}/scripts/voice_cast.py <project> --episode EP001 --pretty

# 3. 把音色参考回写到校验认的两个位置（视觉设定 + 视频提示词）
python3 {技能目录}/scripts/voice_sync.py <project> --episode EP001 --pretty
python3 {技能目录}/scripts/voice_sync.py <project> --episode EP001 --write   # 确认后落盘

# 4. 文档齐备后导出画布：人物音频节点 + 音频到对白视频节点的连线
python3 {技能目录}/scripts/voice_apply.py <project> --episode EP001 --out EP001.voice.canvas.json
```

已经用 `$short-drama-canvas` 导出过画布时，用 `--merge` 并成一份完整画布，
不必手工拼接——两个脚本共用同一套节点 ID，音频连线会精确落到那边的视频节点上：

```bash
python3 {技能目录}/scripts/voice_apply.py <project> --episode EP001 \
  --merge EP001.canvas.json --out EP001.full.canvas.json
```

合并只**追加**，不覆盖既有节点与连线。

脚本一律通过 `dramaScript` 执行，`skill` 填 `short-drama-voice`，
`projectRoot` 填项目根目录。本环境没有 shell。

## 第一步：给人物定音色

音色由**一段参考音频**承担，不由形容词承担。文字只承担参考音频承担不了的三件事：
**选型判据**、**专名发音**、**最易混的角色是谁**。
这一步的规则细节见 [选型与绑定](references/voice-casting.md)，此处只写流程。

**谁需要配音**：`剧本.md` 里有对白的人物。只出现在动作叙述里、从不开口的人不配音，
但要在配音本里明确记一条「本集无声」——沉默是有意的决定，不是遗漏。

**参考音频从哪来**：两条来路，任选其一，优先创作者已有的录音。

- **创作者提供的录音**：放在 `输入/` 下，配音本里写项目相对路径。
- **预置音色合成**：没有录音时用预置音色合成一条试听，它就是该人物的参考音频。
  合成按 `$short-drama-produce` 的 `tts` 模态走，一条有边界的 job、一次明确的确认。

**合成试听要用的两样东西，就是本技能的核心产物**：

1. **参考文本**：一段用来试听的文本，**带朗读内容**，不是描述。它要说清这个人物
   说话的样子——用两三句该人物真实会说的话，让听的人能判断音色对不对。
   同时它也是语音模型的 `reference_text`：告诉模型参考音频里念的是什么。
2. **语音指令**：对这个人物声音的方向控制。写身份，不写情绪——
   音区、质感、语速习惯、口音范围。同一人物在每句台词上挂的是**同一条**指令
   与**同一段**参考音频；单句的情绪另由表演说明承担。

合成后的音频落在 `剧集/<EP>/制作成果/audio/`，路径写进配音本的「声音参考」行。

**没有可听证据时不要写结论**。只有文件名或文字描述时，状态记 `unverified`，
不得声称已确认音色或口音。

## 第二步：写配音本

产物是 `剧集/<EP>/配音本.md`。它逐句记录这个人物怎么说，结构如下：

```markdown
# EP001 配音本

- 音色方案：预置音色合成 | 创作者提供录音
- 生成模型：（账号实际可用的语音模型，由创作者指定）

## 人物 · 卢修斯·瓦伦丁

- 别名：卢修斯
- 声音参考：制作成果/audio/voice-lucius.mp3（用途：音色参考；控制：音色质感、语速基线；不得控制：这条里的情绪、录音空间、背景内容；状态：audibly_inspected）
- 参考文本：陛下，北方的雾比往年更沉。我从十六岁起就守在黑崖堡，从没见过这样安静的雾。
- 语音指令：gender Male; pitch Medium-low; age Young adult; pace measured and unhurried; timbre warm with a slight rasp; accent Standard.
- 最易混：加勒特·罗兰萨斯——两条声线同在中低音区、语速偏慢。区分判据：卢修斯句尾收住不拖长，加勒特句尾常带一段下沉的余音。

### LINE-EP001-001（EP001-SC002）

- 说话人：卢修斯·瓦伦丁
- 场次：EP001-SC002 外 · 王宫长廊与露台 · 日（明亮日光）
- 语气：逗弄晚辈的松弛与纵容，语速偏慢，句尾微微上扬
- 朗读文本：（逗弄地，放慢语速）看好了，这一剑不用挡。
- 参考音频：制作成果/audio/voice-lucius.mp3
- 画布节点：MOTION-EP001-006
```

**`别名` 字段是简称到全名的桥**：`剧本.md` 惯用简称（`卢修斯`），
《视觉设定.md》惯用全名（`卢修斯·瓦伦丁`），写一行别名让脚本对得上。
群像角色（`同伴`、`另一名士兵`）也要写，指向它所属的群体条目（`搜巡士兵`）。

配音本是**工作稿**——音色参考与逐镜绑定还要回写到规范位置，见下一节。

### 逐句语气怎么写

语气写**怎么说**，不写**说了什么**。每条含三样：情绪的落点、语速与停顿、音量或气息。
能转成演员一个动作或表情的留下，转不成的删掉。

判断标准：把语气说明单独拿给一个配音员，他照着说出来的效果是否符合剧本意图。
符合就够，不符合就是写得太空——把「愤怒」换成「压着嗓子，字咬得很重，句尾不放」。

`剧本.md` 里已有的表演括注（如「抓着倒地者的衣领」「声音发抖」）要**吸收进来**，
不与原注冲突。原注是写作者写的，配音本是把它们扩写成可执行的语气方向。

### 朗读文本怎么拼

`朗读文本 = （语气说明）原句`

- `（语气说明）`：从本条的「语气」字段压缩成一句最精炼的括注，可直接进语音模型的文本。
- `原句`：`剧本.md` 里那句话的**逐字原文**，包括标点，一个字都不改。

没有对白的镜次（纯动作、纯环境）不建 LINE 条目。

### 参考文本 vs 朗读文本

两者都在「参考文本」和「朗读文本」字段里，别弄混：

- **参考文本**：每人一条，全剧不变，用来说明「这个人物的声音长什么样」，
  同时是语音模型的 `reference_text`。它是音色的载体。
- **朗读文本**：每句一条，随时在变，是这句台词实际要念出来的东西。

## 回写规范位置（必须做）

配音本是**工作稿**，不是音色的登记处。跨文档校验只认两个既有位置，
音色定了之后必须回写过去，否则校验收不了：

**① 《视觉设定.md》的人物条目 —— 登记音色参考**

每个开口的人物，在它的 `## 人物 · <名>` 条目下加一行（**只能一行**，重复会被校验判错）：

```markdown
- 声音参考：制作成果/audio/voice-lucius.mp3（用途：音色参考；控制：音色质感、语速基线；不得控制：这条里的情绪、录音空间、背景内容；状态：audibly_inspected）
```

路径打头，放在 `- 状态变化：` 之后、`- 画面代称：` 之前。校验器按这一行找到音色参考，
并在下方 `参考音频` 行核对路径是否一致。

**② 《视频提示词.md》的 MOTION 条目 —— 绑定该镜的参考音频**

每个含对白的镜头，在它的 `MOTION-*` 条目里加一行 `- 参考音频：`，语法固定：

```markdown
- 参考音频：REF-VOICE-LUCIUS（顺序：1）· 制作成果/audio/voice-lucius.mp3《卢修斯音色》（用途：音色；角色：卢修斯·瓦伦丁；控制：音色质感；不得控制：台词、语气、情绪）
```

硬性要求（校验器逐条核对）：

- 槽位名 `REF-<大写>` 与图片槽位不重名；顺序从 1 连续编号，**与图片分开数**；
- 用途只能写 `音色`；
- 必须有中文名（`《…》`）；
- `不得控制` 至少包含 **台词、语气、情绪** 三项；
- `角色` 必须是《视觉设定.md》里实际存在的人物条目名；
- **路径必须与《视觉设定.md》里那条声音参考一致**；
- **该人物在本镜的可复制提示词里必须真的说了话**——不说话的人物不绑参考音频。

多句对白在同一镜时，同一人物只绑一条；不同人物各绑一条，用 `；` 连接。

### 为什么不能只写配音本

配音本里那份 `- 声音参考：` 是给人读的工作记录；
校验器、生产、剪辑读的是上面那两个位置。两处都要有，且路径必须字面一致。
回写完再跑一次 `$short-drama` 的校验确认通过。

## 群体条目不能承载多个独立音色

《视觉设定.md》的人物条目**一个只登记一条声音参考**（校验器对重复直接判错）。
所以下面这种情况必须先回 `$short-drama-assets` 处理，不能靠配音本绕过去：

**一个群体条目下有多个人物在说话**。例：视觉设定的 `## 人物 · 搜巡士兵` 是「五名士兵」，
而剧本里 `同伴`、`年长士兵`、`另一名士兵` 都在说话——三个人三副嗓子，
但视觉设定只有一条 `搜巡士兵` 条目。

这时**不能**给三个人各绑一条音色：校验器会报
`参考音频路径与《视觉设定.md》登记的声音参考不一致`。

处理办法，二选一：

1. **拆条目**（推荐，说话的人真的不同时）：回 `$short-drama-assets`，
   把有独立台词的个体拆成自己的 `## 人物 · <名>` 条目，各自登记声音参考。
   群像里没有独立台词的成员继续留在群体条目里 —— 他们本来就不需要音色。
2. **共用音色**（他们本来就该是同一个声音时）：群体条目登记一条，
   所有说话人绑同一条，配音本里也只用一条音色记录。

判断依据：**这几个人在成片里听起来是不是同一个人**？是 → 共用；不是 → 拆条目。

### 校验器还要求「本镜真的说了话」

`- 参考音频：` 行绑定的人物，必须在**该镜的可复制提示词正文里真的说出**
《剧本.md》记在其名下的台词。校验器按引文核对：

- 该镜提示词里没有这个人物的台词引文 → 报「不说话的人物不绑定参考音频」；
- 引文在《剧本.md》里同时属于多人 → 报「看不出是不是该人物在说」，要在引文前点名说话人。

所以回写要在视频提示词的正文写法稳定之后再跑——正文里还没有台词的镜头，先别绑。

## 第三步：落到画布

文档定稿后才进画布。画布上的施工方式是：

| 文档事实 | 画布形态 |
|---|---|
| 人物有音色参考 | 1 个音频节点，标签 `VOICE-<人物> · <人物名>` |
| 语音指令 | 该音频节点的「语音指令」输入区 |
| 参考文本 | 该音频节点的「待朗读文本」输入区 |
| 该人物每一句对白 | 音频节点的音频输出 → 该镜视频节点的 `in` 端口 |

**一人一节点**：同一个人物的所有对白共用同一段参考音频与同一条语音指令，
改一次全局生效。这与「同一角色每句挂同一段参考音色」是同一条约束的两种表述。

节点类型名以 `getCanvas` 返回的 `availableNodeTypes` 为准（本机形态为
`remote-comfyuiAudioNode`）。参数一律先 `node:getConfig` 读当前值与可选范围，
再 `node:setConfig` 写入，`providerId` 与 `modelId` 成对提供。

音频节点必须选**带参考音频能力**的模型：`getConfig` 返回的模型列表里
`referenceAudio` 为真的那些。选了不支持的模型，接上去的音频会被静默丢弃。

### 导出的画布文件

`voice_apply.py` 产出独立的 `.canvas.json`，由创作者导入工作区。它只导出新文件，
不修改任何正在打开的画布。与 `$short-drama-canvas` 的画布合并时用 `--merge`：
两边用同一套节点 ID，`voice_apply.py` 的音频连线会直接命中那份画布的视频节点。

### 台词的画布落点怎么定

配音本的每个 `LINE-*` 都要指向一个 `MOTION-*`。落点按这个顺序取：

1. LINE 条目里显式写的 `- 画布节点：MOTION-...`（最准，推荐）；
2. 按 LINE 的场次找该场次最后一镜——`分镜.md` 的 `来源` 字段写出场次，
   `视频提示词.md` 的 `分镜` 字段指向 SHOT，三跳落到 MOTION。

两处都定位不到时，脚本把这条如实报进「未定位条目」，不猜、不塞进别的镜头。
一场里有多句对白时，给每句写明 `画布节点`；否则它们会全落到该场最后一镜上。

## 边界

- **不写台词**：`剧本.md` 是台词的唯一来源，本技能只读。
- **不改视觉形象**：人物外观归 `$short-drama-assets`，本技能只碰「声音方向」那一段。
- **不做混音**：对白 ducking、配乐落点归 `$short-drama-edit`。
- **不生成视频**：视频提示词归 `$short-drama-video-prompts`，本技能只把音频接到视频节点上。
- **参考音频不是代码产物**：那是录下来的或合成出来的真实文件，本技能负责绑定与记录。

## 已知限制

- 参考音频合成依赖 `$short-drama-produce` 的 `tts` 模态与可用的语音模型；
  模型与音色 ID 都必须由账号与文档显式给出，本技能不内置音色清单。
- 生成是后台任务，未实际回听前不得声称音色已确认。
- 画布节点类型、函数名、参数结构随实际安装内容变化；每次以 `getCanvas`、
  `getNodeTools`、`node:getConfig` 的返回为准，不使用本文档里的型号当固定值。
